# ACG525 UART forwarder

This project forwards raw UART bytes from Raspberry Pi 4 GPIO14/TXD0 to the
ACG525 onboard CH9102F USB-UART bridge. Both sides use 115200 baud, 8N1.

## Directory layout

```text
demo_connect_pi4/
|-- demo_connect_pi4.gprj   # Open this file in Gowin IDE
|-- connection.json         # Pi host/user and laptop COM settings
|-- src/
|   |-- uart_forwarder.v
|   |-- uart_rx.v
|   `-- uart_tx.v
|-- sim/
|   `-- uart_forwarder_tb.sv
|-- constraints/
|   |-- acg525.cst
|   `-- acg525.sdc
|-- scripts/
|   |-- run_sim.ps1
|   |-- build_gowin.ps1
|   `-- run_pi_fpga_test.ps1
|-- demo_rpi4/
|   `-- uart_tx_pi.py
|-- release/
|-- impl/                 # Generated by Gowin
`-- build_gowin.tcl
```

Keeping the Pi script in `demo_rpi4/` versions the host-side stimulus together
with the RTL and prevents protocol settings from drifting between repositories.

## Verification and build

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_sim.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_gowin.ps1
```

Verified with Icarus Verilog and Gowin Designer V1.9.11.03 Education:

```text
UART_FORWARDER_TB_PASS bytes=264 framing_rejected=1 overflow=0
Setup violated endpoints: 0
Hold violated endpoints : 0
Post-route Fmax          : 301.114 MHz (50 MHz required)
Logic latches            : 0
```

The released programming file is `release/uart_forwarder.fs`.

To use the graphical IDE, open `demo_connect_pi4.gprj` from this directory.
The project already contains the device, all RTL sources, CST and SDC; select
the `uart_forwarder` top module if the IDE asks for confirmation, then run
Synthesis -> Place & Route -> Generate Bitstream.

## Raspberry Pi setup

Use `sudo raspi-config`: Interface Options -> Serial Port, disable login shell
and enable the serial hardware. Then install PySerial in a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install pyserial
python3 demo_rpi4/uart_tx_pi.py --start 165 --count 4 --interval 0.5
```

Connect Raspberry Pi physical pin 8 (GPIO14/TXD0) to ACG525 P6-GPIO0/C17 and
connect Raspberry Pi GND to ACG525 GND. Use TTL 3.3 V only. Never connect RS-232
voltage levels or 5 V to C17. V8 is already routed to the onboard CH9102F; do
not attach a second external transmitter to V8.

The FIFO is four bytes deep. It prevents ordinary RX/TX handoff loss, but no
finite FIFO can absorb an indefinitely faster input baud clock. The supplied Pi
demo sends paced bytes; the self-checking simulation also verifies a 256-byte
back-to-back burst at nominal baud.

## One-command laptop test

First configure SSH public-key login from the laptop to the Pi and copy this
project's `demo_rpi4/` directory to `$HOME/demo_connect_pi4` on the Pi. Adjust
`connection.json` for the actual Pi address, user and CH9102F COM number. Then
run from PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_pi_fpga_test.ps1
```

The script starts the Pi sender over SSH while the laptop reads the FPGA's V8
output from CH9102F. It validates the exact raw-byte sequence and prints
`RESULT=PASS` only after all bytes match.
